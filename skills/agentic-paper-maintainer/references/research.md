# 检索、证据与导读

## 增量检索

先查看 `papers.json` 的 ID、标题、版本、核验日期，以及相关主题 README 中的已知缺口。新年份/新术语可扩展检索，不将以下词当成固定白名单：

| 方向 | 检索线索 |
| --- | --- |
| 离线 | agentic RL rollout scheduling / orchestration / environment interaction / trajectory / long tail / group completion |
| 在线 | agent serving / program-aware inference / tool-aware scheduling / KV cache / agent fairness / SLO goodput |
| 沙箱 | agent sandbox / environment provisioning / checkpoint restore / statepoint / fork / pause resume / microVM |

结合 arXiv、系统与机器学习会议官方录用列表、作者机构主页、项目页和官方代码仓库。搜索结果只作线索；最终技术与发表判断回到一手来源。核对首发时间、当前 PDF 版本时间、录用时间，不能把三者混写。下载优先选择官方开放 PDF，并固定版本。

候选判断记录在任务工作记录中；有长期复查价值时才保存额外候选清单。不要为每轮更新增加无实际用途的日志文件。

## 预印本质量

综合具体系统问题、机制与实验可信度，以及以下可核验信号筛选，不设置机械的全满足门槛：

- 作者与机构的相关研究背景；大学或学者声誉是辅助证据，不能替代阅读正文。
- 正式录用：优先会议/期刊官方页面；作者自述与官方确认区分，Workshop 与主会区分。模板、页眉、投稿声明不能证明录用。
- 代码与工件：打开作者给出的仓库，判断是否真的提供实现、安装或实验说明。组织首页、空仓库、计划开源不能写成完整开源。
- 引用：只有拿到可追溯来源和查询日期才记录数量；不以 GitHub stars 代替引用，新论文引用少也不能直接判低质。
- 实验：是否有合理基线、配置、负载、消融与结论范围。工程报告可以收录，但与经过对比评估的系统论文分别描述。

`quality_evidence` 应说明此篇为什么值得收录，不写笼统“高质量论文”。P0/P1/P2 表示本库阅读顺序与研究贴合度，不代表学术质量等级。

## 每篇导读

先读摘要、引言、系统图、设计、实验与结论；关键数字和硬件配置核对正文/附录。表格或图的信息提取不可靠时查看 PDF 对应页面，不能凭抽取残片补全数字。

| 字段 | 写作要求 |
| --- | --- |
| `overview` | 一段连贯中文：研究什么、关键做法、为什么与 Agent 执行系统有关。不要只翻译摘要。 |
| `scenario` | 服务对象、工作负载、调用链与系统边界；说明离线/在线、模型/工具/环境各在哪一层。 |
| `motivation` | 具体瓶颈和触发条件、既有方法依赖的假设为何失效。区分作者实验证据与自己的分析，不虚构“所有前人都未解决”。 |
| `mechanism` | 调度/恢复的单位、输入信号、决策、状态保存与迁移、执行路径，以及核心贡献。避免仅堆模块名。 |
| `evaluation` | 硬件数量与型号、模型及规模、数据集/任务、并发与负载、对照系统及版本、指标、关键结果和消融。未披露的配置直接说明。 |
| `limitations` | 适用条件、证据缺口、不能外推的范围，以及与本库研究线的边界。 |
| `evidence` | 将关键场景、机制与实验映射到实际 PDF 的章节和物理页码；每条 `note` 说明这些页支撑什么。不要机械要求固定条数。 |

保持硬件与实验范围一致：单节点、集群实验、生产规模不是同一数据；只写 Hopper 不能自行补成 H100。GPU 小时、训练步数、token 吞吐与任务 goodput 不能互换。说明结果是完整真实执行、部分真实推理、轨迹重放、仿真、微基准还是生产报告。

小规模建议写入 `small_scale_entry`：可独立验证的机制、所需环境、一个有力的简单基线、主要指标和验证局限。允许建议 CPU / API / 重放先筛方案，但不能宣称它们已证明训练质量等价或生产收益。

## PDF 版本更新

同一 arXiv ID 或同一工作的会议版通常是更新而非新增。保留稳定 ID，使阅读 URL 与收藏持续有效。比较新旧版本中与导读相关的设计、实验和状态，重新计算页码、页数、字节数及 SHA-256；不能只换 PDF 不改证据页码。

原来由用户提供且明确要求保留的文件先保留；新版本需要替换时依据当前用户指令处理，不擅自丢弃指定版本。普通可追溯版本更新无需把所有旧 PDF 复制进目录；Git 历史可保留旧版。跨目录重分类同步所有引用，不额外复制同一 PDF。
